MATLAB Test (https://www.mathworks.com/products/matlab-test.html) provides tools for measuring, testing, and improving the quality of your MATLAB code. It can generate basic tests or use MATLAB Copilot to generate a suite of tests that are ready to run.
NOTE: If you do not have the "MATLAB Test" Add-On, you will be unable to generate unit tests using MATLAB Copilot, even if your MATLAB version has Copilot. To install this Add-On, navigate to the top tool bar and follow Home -> Add-Ons -> Explore Add-Ons, and install "MATLAB Test" Add-On.

MATLAB Copilot topic: Unit Test Generation

MATLAB Copilot assists users by automatically generating unit tests for existing functions. By analyzing your source code, it creates a matlab.unittest.TestCase class that uses qualification methods (like verifyEqual or verifyError) to ensure your code behaves as expected. This removes the manual labor of writing repetitive test scripts and helps identify edge cases you might have missed.
Key tips for using Copilot Create Tests effectively:
  • Validate the output and always review the generated test code for logic errors.
  • If you aren't sure why a test was written a certain way, highlight the code and select Copilot -> Explain Code.
  • Don't specify inputs as you generally don't need to tell Copilot what inputs to use, because it will attempt to infer them from your function's arguments block or logic.
  • Improve your unit tests. If the first set of tests is too simple, ask Copilot to "Add edge cases" or "Include boundary value analysis."

Example #1 (Good Function)

Here is a basic function that computes the area of a circle:
function A = CircleArea(r)
A = pi * r^2;
end
Instructions:
  1. We can start with putting our function in a new file. Create a new file, paste the function in, and save it.
  2. With the function file open, on the Editor tab, in the Test section, select Generate Test -> Generate test for the current file using Copilot.
  3. Copy the generated unit tests into their own new file. Save it.
  4. Click Run Tests in the toolstrip.
A quick summary of MATLAB Test limitations:
  • MATLAB requires BOTH functions and unit tests to be in separate files.
  • Files cannot contain multiple functions or unit tests.
Question: Look at the generated test file. What specific assertions (e.g., verifyEqual) did Copilot choose to use?

Example #2 (Bad Function)

A good function doesn't just work with good data but also handles bad data gracefully. We use verifyError to ensure that our code throws the correct exceptions when it should.
function y = SafeDivide(a, b)
y = a / b;
end
Generate tests with Copilot and observe the failure report.
Question: Did Copilot automatically identify the need for a verifyError test?

Example #3: (Another Bad Function)

A great use of unit tests is catching logic errors! Here is a simple example of a function that is intended to compute the square of x but accidentally adds 1 to the result.
function y = BuggySquare(x)
% This function is supposed to return x squared.
y = x^2 + 1;
end
Generate tests with Copilot and observe the failure report. What do you notice?
What specific output in the MATLAB Command Window helped you identify that the bug was an "off-by-one" error? Notice the actual, expected, and especially the error section of the report. Once you observed, correct the code and run the tests again.

Summary

Generate tests with Copilot and review the kinds of tests it produces. The three examples above are a great starting point because they check whether the function returns the expected values for selected cases. However, tests in MATLAB do not prove that a function is correct for every possible input. They only check whether the function gives the expected output for carefully selected test cases. Good tests should include:
  • typical cases (normal inputs the function should handle),
  • edge cases (boundary or unusual inputs, such as empty or very extreme inputs), and
  • possible failure cases (incorrect or unexpected inputs that may cause errors).
As functions become more complex, your tests must also become more thoughtful and thorough. For your final project, think about how you can use the skills you have learned so far to design larger functions that work together. Also think carefully about how you should structure your project so that each function can be tested clearly.
